# موبایلر — فروشگاه + پنل مدیریت (یک پروژه، یک دیتابیس)

Next.js 15 (App Router) + MongoDB Atlas (Mongoose) + Tailwind (فروشگاه) — قابل دیپلوی مستقیم روی Vercel.

| آدرس | چیست |
|---|---|
| `/` | فروشگاه (ویترین پویا، جستجو و فیلتر، دسته‌بندی‌ها، پیشنهادهای ویژه، سبد خرید و ثبت سفارش) |
| `/admin` | پنل مدیریت (نیاز به ورود) |
| `/api/products` | API عمومی محصولات برای فروشگاه |
| `/api/orders` | ثبت سفارش از فروشگاه (قیمت از دیتابیس، کنترل موجودی و کسر اتمیک) |
| `/account/notifications` | اعلان پاسخ پشتیبانی برای مشتری |
| `/api/account/notifications` | API اعلان‌ها و وضعیت خوانده‌شدن پاسخ مدیر |
| `/api/admin/*` | APIهای پنل (همه پشت ورود) |

## فروشگاه موبایلر
- صفحه اصلی بازطراحی شده با هویت بصری سرمه‌ای، نارنجی و سفید، طراحی واکنش‌گرا و انیمیشن‌های ملایم.
- جستجوی زنده در کاتالوگ، فیلتر دسته‌بندی، مرتب‌سازی قیمت و محبوبیت، جزئیات محصول و سبد خرید.
- ثبت سفارش از طریق API موجود؛ اطلاعات مشتری و شماره موبایل و روش پرداخت نقدی/درخواست اقساطی در سفارش ذخیره می‌شود.
- برای هر یک از ۱۰۰ محصول نمونه، تصویر گرافیکی اختصاصی دسته‌بندی در `public/img` نمایش داده می‌شود؛ تصاویر فعلی عکس واقعی کالا نیستند.

نام دیتابیس در اتصال فروشگاه و همه اسکریپت‌های seed برابر `mobiler_db` است تا فروشگاه و پنل از یک دیتابیس مشترک استفاده کنند.

## چه چیزی واقعاً به دیتابیس وصل است
- **انبار** (`/admin/inventory`): لیست، افزودن، ویرایش قیمت/موجودی، حذف — همان کالکشن `products` که فروشگاه می‌خواند. تغییر در پنل بلافاصله در فروشگاه دیده می‌شود (فروشگاه موجودی را هر ۱۰ ثانیه تازه می‌کند).
- **فروش** (`/admin/sales`): سفارش‌های کالکشن `orders`؛ تغییر وضعیت. لغو سفارش موجودی را به انبار برمی‌گرداند.
- **داشبورد** (`/admin`): فروش امروز، سفارش‌های در انتظار، سلامت انبار و آخرین سفارش‌ها زنده‌اند.

## پشتیبانی و اعلان‌ها
- پیام مشتری در `SupportConversation` ذخیره می‌شود و در صندوق ورودی `/admin/messages` به مدیر نمایش داده می‌شود.
- اعلان‌های پنل `/admin/notifications` پیام‌های خوانده‌نشده‌ی پشتیبانی را همراه با لینک مستقیم به مکالمه نشان می‌دهد.
- پاسخ مدیر در همان مکالمه ذخیره می‌شود؛ تعداد اعلان خوانده‌نشده‌ی مشتری افزایش می‌یابد و در `/account/notifications` نمایش داده می‌شود.
- مهمان پس از ثبت‌نام و تأیید همان شماره موبایل، مکالمه‌ی قبلی‌اش به حساب متصل می‌شود.
- اعلان‌ها از دیتابیس خوانده می‌شوند؛ به‌روزرسانی صفحه باعث از دست‌رفتن پیام‌ها نمی‌شود.

## داده‌های آزمایشی
`npm run seed:demo` داده‌های ساختگی و برچسب‌دار برای مشتریان، پرونده اعتباری، تحلیل ایجنت، سفارش‌ها و مکالمه‌های پشتیبانی ایجاد می‌کند. این دستور idempotent است و داده‌های موجود را حذف یا بازنویسی نمی‌کند. محصولات را ابتدا با `npm run seed` اضافه کنید تا سفارش‌های نمونه نیز ساخته شوند.
- شماره‌های نمایشی از `09990000100` به بعد و رمز نمایشی `Demo@12345` است.
- این اطلاعات صرفاً برای محیط توسعه و نمایش هستند؛ شماره‌ها، هویت‌ها و اطلاعات مالی واقعی نیستند.
- برای پاک‌سازی دستی داده‌های دمو فقط اسناد دارای `synthetic: true` و سفارش‌های با کد `DEMO-` را هدف بگیرید؛ این seed هیچ داده‌ای را حذف نمی‌کند.

## محدودیت‌های باقی‌مانده
- درگاه پرداخت آنلاین اقساطی پیاده‌سازی نشده؛ تأیید سفارش اقساطی و ایجاد جدول اقساط همچنان با اقدام مدیر انجام می‌شود.
- پیامک در حالت شبیه‌ساز است؛ برای محیط عملیاتی باید provider واقعی اضافه شود.
- داده‌های اعتبارسنجی synthetic هستند و به سامانه بانکی یا اعتبارسنجی بیرونی متصل نیستند.
- محدودکننده‌ی درخواست در صورت تنظیم `UPSTASH_REDIS_REST_URL` و `UPSTASH_REDIS_REST_TOKEN` از Redis مشترک استفاده می‌کند؛ در غیر این صورت fallback حافظه‌ای هر نمونه فعال است.

## اعتبار یار: ثبت‌نام، اعتبارسنجی آزمایشی، ایجنت و پشتیبانی (نوامبر ۲۰۲۶)
- ثبت‌نام با نام، موبایل، **کد ملی** و کد تأیید پیامکی: `/account/register` و `api/auth/{otp,register,password,me}`
- پرونده‌ی اعتباری مشتری: `/account/credit` ؛ پیش‌نمایش اقساط در `/checkout` (`api/credit/eligibility`)
- شبیه‌ساز قطعی: `src/lib/credit-sim.js` ؛ ایجنت قاعده‌محور: `src/lib/credit-agent.js` ؛ قوانین نهایی و جدول اقساط: `src/lib/credit-service.js`، `credit-policy.js`
- پشتیبانی: `/account/support` (بات + ارجاع به انسان) و `/admin/messages` (پاسخ مدیر)
- پنل ریسک مدیر: `/admin/risk` و `/admin/risk/[userId]`

نکته‌ها: داده‌ی اعتباری آزمایشی و برچسب‌دار است (`synthetic: true`). ایجنت فقط پیشنهاد می‌دهد؛ سفارش اقساطی در «در انتظار» می‌ماند تا مدیر تأیید کند و جدول اقساط فقط پس از تأیید ساخته می‌شود. کد ملی فقط HMAC و نسخه‌ی ماسک‌شده ذخیره می‌شود. کد پیامکی شبیه‌ساز است (`src/lib/sms.js`؛ در production برای روشن‌ماندن `OTP_SIMULATOR=on`). حساب‌های قدیمی باید کد ملی و تأیید موبایل را در «اعتبار و اقساط» تکمیل کنند.

## تست‌های خودکار دامنه‌ای
- `npm test` دو مجموعه تست سبک را اجرا می‌کند: پایداری داده‌ی اعتباری شبیه‌سازی‌شده و آزمون‌های امتیازدهی، سیاست اقساط، اعتبارسنجی/ماسک کد ملی و ارجاع پاسخ‌گوی هوشمند.
- این تست‌ها به MongoDB یا اطلاعات محرمانه نیاز ندارند و برای بررسی منطق دامنه در محیط توسعه طراحی شده‌اند.

## اجرای محلی
1. `npm install`
2. `cp .env.example .env.local` و مقدارها را پر کنید (`MONGODB_URI` با دیتابیس `mobiler_db`، `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `SESSION_SECRET`)
3. `npm run seed` ← افزودن امن محصولات نمونه تا کاتالوگ ۱۰۰‌تایی؛ کالاهای موجود، قیمت و موجودی آن‌ها حذف یا بازنویسی نمی‌شوند.
4. `npm run seed:orders` ← (اختیاری) ۱۲ سفارش نمونه برای دیدن صفحه فروش
5. `npm run seed:demo` ← (اختیاری) مشتریان، سفارش‌ها، پرونده‌های اعتباری و مکالمه‌های ساختگی
6. `npm run dev` ← فروشگاه `http://localhost:3000` و پنل `http://localhost:3000/admin`

## ساختار
```
src/app/(shop)/        فروشگاه؛ صفحه اصلی در shop/page.js و با rewrite روی / نمایش داده می‌شود
src/app/(admin)/admin/ پنل مدیریت (Root Layout و CSS مخصوص خودش)
src/app/api/           APIها
src/admin/             کامپوننت‌ها و ترجمه‌ی پنل
src/components/        کامپوننت‌های فروشگاه
src/models/            Product, Order (مشترک)
src/lib/               db، auth، catalog
src/middleware.js      قفل‌کردن /admin و /api/admin
```
فروشگاه و پنل دو Root Layout جدا دارند تا CSS سراسری پنل روی فروشگاه (و برعکس) اثر نگذارد.


## کالاها
کالاها را از `/admin/inventory/new` اضافه کنید؛ دیتابیس خالی = فروشگاه خالی (کاتالوگ نمایشی حذف شده است).

## پرداخت نقدی (درگاه آزمایشی)
سفارش نقدی ← `awaiting_payment` ← صفحه‌ی `/pay` (شبیه‌ساز) ← پرداخت موفق ← تأیید خودکار (`confirmed`) و ثبت `payment.ref`. سفارش‌های پرداخت‌نشده بعد از ۳۰ دقیقه لغو و موجودی‌شان برگردانده می‌شود و در پنل ادمین نمایش داده نمی‌شوند. سفارش اقساطی مثل قبل در وضعیت «در انتظار» برای بررسی اعتبار می‌ماند. برای خاموش‌کردن شبیه‌ساز: `PAYMENT_SIMULATOR=off`.

## مدیران پنل (چند مدیر هم‌زمان)
- **مدیر کل**: با `ADMIN_EMAIL` و `ADMIN_PASSWORD` در تنظیمات سرور وارد می‌شود و قابل حذف یا غیرفعال‌شدن نیست.
- **مدیران دیگر**: مدیر کل از صفحه‌ی «مدیریت مدیران» (`/admin/admins`؛ آدرس قدیمی `/admin/users` به آن هدایت می‌شود) با نام، ایمیل (مثلاً Gmail) و رمز، مدیر اضافه می‌کند. هر مدیر با ایمیل و رمز خودش وارد می‌شود و چند نفر می‌توانند هم‌زمان در پنل باشند.
- مدیر کل می‌تواند مدیری را غیرفعال، حذف یا رمزش را عوض کند؛ دسترسی مدیر غیرفعال/حذف‌شده در درخواست بعدی قطع می‌شود.
- فقط مدیر کل به مدیریت مدیران دسترسی دارد (`/api/admin/admins`)؛ گزینه‌ی آن برای مدیران عادی در منو دیده نمی‌شود.
- ورود مدیر محدودیت تعداد تلاش دارد (۱۰ بار در ۱۵ دقیقه به ازای هر IP؛ در Vercel برای محدودیت واقعی از Upstash/Redis استفاده کنید).

## سفارش‌ها: صفحه‌بندی، جزئیات و وضعیت «ارسال‌شده»
- **صفحه‌بندی سمت سرور**: `GET /api/admin/orders` و `GET /api/admin/customers` با `page` و `pageSize` (پیش‌فرض ۲۰، حداکثر ۱۰۰) و فیلترهای `q`، `method`، `status`، `period`، `min`، `max` (سفارش‌ها) و `q`، `sort`، `mode=new` (مشتریان) کار می‌کنند. جمع‌ها و کارت‌های بالای صفحه از کل دیتابیس محاسبه می‌شوند، نه از صفحه‌ی جاری.
- **مالی**: جمع‌ها با aggregate روی همه‌ی سفارش‌ها محاسبه می‌شود (قبلاً فقط ۵۰۰ سفارش آخر بود). تفکیک‌ها در `/api/admin/finance/groups` است و در بُعد «دسته» مبلغ هر ردیف کالا به دسته‌ی همان کالا می‌رسد.
- **خروجی CSV**: `/api/admin/orders/export` و `/api/admin/customers/export` همه‌ی نتیجه‌ی فیلتر (سقف ۲۰٬۰۰۰ ردیف) را می‌دهند. همه‌ی سلول‌ها از `src/lib/csv.js` رد می‌شوند تا سلولی که با `= + - @` شروع شود در Excel فرمول نشود.
- **جزئیات سفارش**: `/admin/sales/[id]` (مشتری و آدرس، اقلام، پرداخت، سابقه‌ی وضعیت).
- **قاعده‌ی انتقال وضعیت** (`src/lib/order-flow.js`): `pending → confirmed → shipped → completed`؛ لغو فقط از `pending` و `confirmed` (بعد از ارسال، کالا از انبار خارج شده است). انتقال نامعتبر پاسخ ۴۰۹ می‌گیرد و شرط روی خود سند اعمال می‌شود تا درخواست هم‌زمان آن را دور نزند.
